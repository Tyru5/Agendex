# Live plan approval

Agendex can hold Claude Code’s `PermissionRequest` for `ExitPlanMode` until a reviewer decides in the authenticated local app. Start the OSS API and client, then run:

```sh
agendex hooks install claude-code --scope repo
```

Restart Claude Code. The installer writes `.claude/settings.json` (or `~/.claude/settings.json` with `--scope user`), preserves unrelated settings/hooks, and backs up existing files. Uninstall also removes older Agendex entries in `.claude/hooks.json`. Other hooks returning a deny still take precedence.

Open **Reviews** in the local dashboard to read the immutable snapshot and approve, request changes with feedback, reject with feedback, or cancel. Approval grants this `ExitPlanMode` invocation and echoes its approved input snapshot via `updatedInput`; request changes denies it, and rejection denies and interrupts Claude. It does not persist permission rules or bypass other permissions. The hook requires `tool_input.plan`, `tool_input.planFilePath`, and `session_id`; missing/invalid input returns explicit deny JSON instead of guessing a different session’s plan. Claude Code 2.1.285 fixed stale/missing ExitPlanMode plans in hooks; upgrade when the hook reports missing content.

## Another device

Reach the existing OSS app over your tailnet or configured reverse proxy and sign in with its local API token. The Reviews queue uses the same authenticated `/api/v1` routes. Named cloud identities and assigned team reviewers are separate from this local token account.

The hook contacts `http://127.0.0.1:4890` by default; `AGENDEX_REVIEW_URL` or `--server <origin>` selects another existing server. Set `AGENDEX_TOKEN` to that server’s existing local API token if it differs from the saved token. No token is generated by the waiting command, and no bearer or owner secret appears in URLs or the review list.

## Manual review

```sh
agendex review-plan --file ./plan.md --timeout 1800
```

This blocks the command until a decision, prints JSON, and exits zero only when approved. It rechecks the file before every heartbeat and before acknowledgement; editing or deleting it invalidates approval. This is useful in explicit agent workflows; it does not automatically prevent unrelated commands from implementing the plan.

Claude’s snapshot and absolute file path come from its injected tool input. The hook verifies the disk content initially, during every heartbeat, and before final acknowledgement. A changed plan requires a new invocation and a new review; approvals cannot be reused across requests or sessions.

## Lifecycle and limits

The hook waits at most 30 minutes by default (`--timeout` accepts 1–3600 seconds). Waiting clients heartbeat every second. A missed heartbeat for 60 seconds marks a review disconnected, including an approved decision not yet acknowledged. Expiry, cancellation, revision change, API failure, and client signals deny rather than grant. Final acknowledgement atomically checks owner, live status, and revision; retries return the same acknowledgement. Cancellation cannot retract a decision already received by the agent.

The process-local queue holds at most 200 sessions and removes terminal records an hour after their expiry. Restarting the server clears the queue and never replays grants; a waiting hook denies when its session disappears. The queue is live coordination, not a durable approval audit log. A terminated hook cannot send a cancellation; its heartbeat lease expires. Browser disconnection alone does not cancel a waiting agent.

## Agent contracts

Only Claude `PermissionRequest` / `ExitPlanMode` is an automatic plan permission gate. Codex `Stop` continues a finished turn when blocked; it does not grant plan permission. Its legacy installer remains behind `--preview` and the command reports unsupported without emitting a continuation decision. Pi’s existing manual commands remain available; they do not install an automatic permission gate. Plannotator approval/annotation integration is unchanged.

Contracts checked against [Claude hook reference](https://code.claude.com/docs/en/hooks#permissionrequest) and [Codex hook reference](https://developers.openai.com/codex/hooks/). In particular, a nonzero Claude command exit alone leaves permission handling unchanged; Agendex always emits the explicit `PermissionRequest` deny object on failures.
